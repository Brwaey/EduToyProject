## 1. 用途与当前执行安排

本文档是整个项目的功能测试入口，说明测什么、怎样测、什么结果才算通过，以及后续新增功能怎样补充用例。面向开发者、测试执行者和课程演示人员。需求以项目说明为准，数据与接口约定以架构和 OpenAPI 为准；发生差异时记录缺陷或设计变更，不直接修改预期结果来迁就实现。

**用户已安排测试在后续集中进行。本次仅编写和检查文档，不运行应用功能测试，不调用真实模型。** 开发继续推进时同步更新本文档，未执行的用例保持“未执行”，不据此阻塞后续开发，也不提前标记验收通过。

## 2. 环境、账号与测试材料

### 2.1 隔离环境

使用 README 的 Python 3.12、Node.js 24 与锁定依赖；不需要 Docker。准备两个独立浏览器会话（不同浏览器配置文件或无痕窗口），以及用于并发冲突的同账号双标签页。

| 环境 | 数据与用途 |
| --- | --- |
| 后端自动化 | pytest `tmp_path` SQLite 和独立主密钥，经真实 Alembic 迁移；不使用日常库 |
| 浏览器自动化 | Playwright 自动创建临时库/主密钥，端口为后端 8001、前端 5174、模拟模型 8099 |
| 手工功能验证 | 独立临时目录；建议后端 8010、前端 5180，与自动化和日常环境分开 |
| 真实模型验收 | 同样使用测试库和虚构材料；用户在测试应用填写自己选择的配置 |

以下是**后续执行时使用的命令，本次不执行**。先从仓库根目录安装 README 所列依赖。在终端 A：

```bash
export EDUTOY_TEST_DIR="$(mktemp -d "${TMPDIR:-/tmp}/yanji-manual.XXXXXX")"
export EDUTOY_DB_PATH="$EDUTOY_TEST_DIR/functional.sqlite3"
export EDUTOY_AI_KEY_PATH="$EDUTOY_TEST_DIR/ai-master.key"
export EDUTOY_PORT=8010
export EDUTOY_ORIGINS=http://127.0.0.1:5180
backend/.venv/bin/python backend/run.py
```

在终端 B，从同一仓库根目录运行：

```bash
EDUTOY_API_TARGET=http://127.0.0.1:8010 npm --prefix frontend run dev -- --port 5180 --strictPort
```

打开 `http://127.0.0.1:5180`。记录终端 A 的临时目录，重复启动沿用该目录；新建目录用于另一批次。接口契约在 `http://127.0.0.1:8010/docs`。涉及故障注入、数据库锁、主密钥缺失、迁移失败和恢复时，**仅操作测试副本**。测试结束后停止自己启动的服务，先保存脱敏证据，再按记录清理该批次临时目录，不删除日常 `data/`。

截图、trace、响应和数据库副本可能包含材料，测试只使用虚构内容。真实 API Key 不写入测试文档、截图、日志、缺陷报告或 Git；检查网络请求时不导出未脱敏的 Authorization、Cookie 和 CSRF 值。

R-1 文件名 `中文实验.md`，UTF-8 内容：

```markdown
# 检索实验：第二次尝试
目标：检查增加训练轮数是否改善检索效果。
行动：保持其他设置不变，完成两次尝试。

协作：AI 提供了初始建议，我补充了对照条件。

```

另准备 UTF-8 BOM 文件、无 Markdown 标题的 txt、空文件、仅空白文本、不合法 UTF-8 字节、恰好 1 MiB 和 1 MiB＋1 字节文件。不合法编码样例不能先经编辑器自动转换。文件大小按字节，AI 材料上限按 Unicode 字符计数，二者分开测试。

### 2.3 模型模拟与真实调用

模拟 HTTP 服务只用于流程和故障验证，不用于科研质量结论。后续需要手工模拟时运行：

```bash
backend/.venv/bin/python backend/tests/mock_model_server.py --port 8099
```

在测试账号配置 `http://127.0.0.1:8099/v1`、虚构 Key `test-only-key`，模型名根据下表选择。服务不接入产品的正式运行入口。

| 模型名 | 当前测试服务行为 |
| --- | --- |
| `test-model` | 固定的合法草稿或一条关系建议 |
| `empty-relations` | 合法空关系列表 |
| `unauthorized` / `limited` / `missing` / `server-error` | HTTP 401 / 429 / 404 / 500 |
| `invalid` / `badcite` | 非 JSON 的生成内容 / 不存在的原文片段 |
| `bad-response` / `huge` / `truncated` / `redirect` | 非 JSON 响应体 / 超过 1 MiB / 输出截断 / 302 |
| `slow` / `timeout` | 分别等待约 2 秒 / 5 秒；不是默认 120 秒超时的直接复现 |

验证超时可在**专用测试后端**启动前设置 `EDUTOY_AI_TIMEOUT=1` 并使用 `timeout`，结束后恢复默认或开启新批次。此配置只缩短验证等待，不改变产品默认 120 秒要求。队列容量、全局并发、迟到响应、数据库写入失败等优先通过可控的后端测试注入，不要求人工碰巧触发时序。当前模拟服务没有覆盖的输出形态，先补充 fixture 再执行，不能称为已覆盖。

真实模型部分执行第 8 节：只填写用户选定服务，不复用其他项目的凭据；保存供应商、模型、日期、任务 ID 和脱敏配置，不保存 Key。

## 12. 缺陷记录与后续同步规则

### 12.1 缺陷模板

缺陷可在 GitHub Issue 或团队指定位置记录，在用例结果中保留可访问链接。无权限创建外部 Issue 时先在测试批次文档登记，不丢失复现信息。

```markdown
- 缺陷 ID / 标题：BUG-YYYYMMDD-01
- 关联用例及需求：FT-… / FR-…
- 代码提交 / 环境 / 模拟或真实模型：
- 严重程度：S0 数据/密钥/权限；S1 主流程不可用；S2 局部错误；S3 展示问题
- 前置数据与最短复现步骤：
- 预期结果 / 实际结果：
- 脱敏截图、请求标识或任务 ID：
- 影响范围 / 临时处理方式：
- 负责人 / 状态：待分配 / 新建、处理中、待复测、已关闭
- 修复提交 / 复测批次及结果：
```

优先级 P0/P1/P2 决定先测什么，严重程度 S0–S3 描述实际缺陷影响。修复代码后先标记待复测，实际重测通过才关闭。

### 12.2 每次开发必须同步的内容

1. **新增功能前**：在对应组追加稳定 ID，写清前置、操作、预期、异常路径和优先级；尚未确定的功能标为待开发，不写成已可用入口。
2. **功能实现或修改后**：同一次功能交付同步本文的功能状态、实际页面/API、字段/枚举/边界、版本与数据流行为，并补充受影响模块的回归用例。
3. **修复缺陷后**：补充可复现该缺陷的用例及测试入口，保留原失败记录；不能只改“通过”字样。
4. **开发完成但暂不测试**：将功能标为已实现、执行仍未执行；在开发进度记“实现完成、待集中验证”。用户本次已要求测试后置，不能自行用历史结果补成新功能通过。
5. **实际运行后**：更新批次总表、逐项结果、命令、代码版本、脱敏证据及剩余问题；同步开发进度的验收状态。
6. **迁移、API 或模型协议变化**：补齐旧库升级、兼容、输入范围、失败恢复与凭据用例；更新自动化映射和环境命令。
7. **范围调整或移除功能**：保留旧 ID 和调整原因，标注替代用例；不删除失败历史，不混淆待开发与不适用。
8. **提交前**：核对本文、README、项目说明、架构和开发进度一致；如果某次变更不影响功能测试，明确记录“无需新增用例”的具体原因。

维护责任：功能开发者负责同步对应用例和代码映射，实际执行者负责结果，缺陷修复者负责复测关联。团队成员尚未分配时写“待分配”，不假设用户已安排人员。仓库根目录 [AGENTS.md](../AGENTS.md) 同步约定，供后续开发继续遵守。
