## 1. 项目定位

### 1.1 一句话介绍

研迹是面向研究生的 AI 协作科研成长支持系统，围绕研究问题连接记录、尝试、证据、个人判断与后续计划，使研究脉络和学习积累可以被回顾、解释和继续推进。

项目仓库：<https://github.com/Brwaey/EduToyProject>

应用场景：软件工程实践课程项目，5 人团队协作开发。首版聚焦研究生个人使用，优先覆盖论文阅读、实验复现和早期研究探索。

### 1.2 核心目标

| 目标 | 产品中可观察的行为 |
| --- | --- |
| 理清研究脉络 | 用户能从一个研究问题追踪到尝试、结果及后续分支 |
| 看见个人贡献 | 用户能指明自己作出的判断、行动及其依据 |
| 回顾能力成长 | 用户能对照前后理解，并找到支持能力变化的实例 |
| 积累探索经验 | 未达预期或暂缓的尝试保留结果、解释、材料和重启条件 |
| 支持自主规划 | 用户能依据证据与资源，选择一个具体的下一步行动 |

自我调节学习在产品中对应“设定目标 → 执行与记录 → 反思 → 调整目标”。帮助用户理解自己的进展和增强掌控感是设计目标；当前没有证据证明产品已提升学习效果或缓解焦虑。

### 1.3 已确定的设计原则

- 按已确定的产品方向直接细化和开发，当前开发计划不设置访谈前置任务。
- 记录入口保持轻量，一句话即可保存，结构化信息可以后补。
- AI 提供有来源的草稿、整理和建议；用户保留修改、拒绝与确认权。
- 贡献与成长通过具体行为和证据呈现，不提供无依据的贡献比例或能力总分。
- 保留“证据不足”“尚不能解释”等状态，不将每次失败自动包装成收获。
- 研究材料默认私有，用户明确选择哪些内容用于模型处理或导出。

## 2. 使用流程与信息架构

### 2.1 主导航

| 页面 | 主要区域 | 常用操作 |
| --- | --- | --- |
| 研究地图 | 项目/主题选择、问题与分支图、节点详情 | 展开脉络、筛选状态、查看证据、添加或修改关系 |
| 科研记录 | 随手记、记录列表、待整理收件箱、探索卡详情 | 保存、导入、整理、确认 AI 草稿、关联主线 |
| 我的成长 | 贡献时间线、能力档案、理解前后对照 | 查看实例、修订表述、补充证据、记录认识变化 |
| 下一步 | 方向池、当前重点、行动列表、复盘入口 | 比较方向、设定计划、更新进展、复盘与调整 |

M1 初次进入时显示真实空状态，提供新建项目、新建记录和导入入口，不自动生成虚构进度。M2 开放研究地图和下一步；M4 开放我的成长，空状态提供创建贡献、标签、实例和理解变化入口。后续再提供明确标注的虚构示例，以及研究问题、上次进展、下一项行动与待整理记录的聚合入口。

### 2.2 典型日常流程

M1 当前可用流程：**注册/登录 → 创建项目或保持未归类 → 输入/导入记录 → 补充个人判断 → 查看原文与历史 → 搜索回顾**。M2 已补上手动研究脉络与行动复盘；下列记录/关系 AI 流程已在 M3 接入，贡献成长与 AI 贡献候选已在 M4 实现，功能验收待集中执行。

1. 用户粘贴一段笔记、实验描述或 AI 对话片段，先保存原始内容。
2. AI 生成探索卡草稿，提出可能的研究主线和关联建议。
3. 用户修改或确认关键判断与关系；未确认内容保留在待整理收件箱。
4. 已确认记录进入研究地图，并可作为贡献、能力变化或下一步计划的证据。
5. 用户复盘本周工作，选择继续、调整或暂缓某个方向，确定下一项行动。

用户也可以手动完成上述流程。AI 调用失败不会导致原始记录丢失或阻止基础操作。

## 3. 基本对象：探索卡

探索卡描述一次有意义的科研活动。保存原始内容时只要求有文本或标题；其余字段按场景补充，不强制一次填完。

| 字段 | 含义 |
| --- | --- |
| 标题与记录类型 | 论文阅读、实验尝试、AI 协作、灵感疑问或随手记 |
| 所属项目与研究问题 | 这次活动服务于什么问题；允许暂未归类 |
| 起因与目标 | 为什么开始，希望弄清什么 |
| 行动与协作 | 做了哪些事，AI 或他人提供了哪些帮助 |
| 结果与观察 | 发生了什么，哪些是已经观察到的事实 |
| 我的判断 | 用户如何理解结果，采纳、修正或拒绝了什么 |
| 来源与证据 | 原始片段、笔记、实验结果或代码/论文链接 |
| 当前状态 | 工作是否进行、受阻、暂缓或已结束，以及结果如何解释 |
| 后续想法 | 待验证问题、候选方向、可复用经验或重启条件 |

原始材料、AI 建议和用户确认内容应可区分。更新判断时保留版本和来源，避免用新认识悄悄覆盖旧认识。

### 3.1 状态约定

工作状态与结果判断分开保存，避免将“完成实验”理解为“假设得到支持”。

| 维度 | 状态 |
| --- | --- |
| 工作状态 | 待开始、进行中、受阻、暂缓、已结束 |
| 结果判断 | 尚无结果、证据不足、当前条件下未支持、初步支持、不适用 |
| AI 建议状态 | 待确认、已采纳、修改后采纳、已拒绝 |

“当前条件下未支持”只描述该次尝试覆盖的条件，不自动推广为普遍否定。结束或暂缓工作时可以记录原因；暂缓时可补充重新考虑的条件。

## 4. 功能规格

### FR-01 科研记录与待整理收件箱

M1 已实现手动记录、五种类型、结构化字段、项目归类、搜索筛选分页、导入、编辑历史与来源版本。M2 增加地图关联入口与研究脉络查询；M3 已实现选择材料、生成探索卡草稿、引用校验、字段对照、采纳/拒绝及 AI 收件箱。

- 提供随手记和四类模板：论文阅读、实验尝试、AI 协作、灵感疑问。
- 首版支持文本输入、Markdown 和纯文本导入，以及添加论文、代码、结果的外部链接。
- 保存原始文本，允许暂不填写项目、结论等字段；提供记录列表、基本搜索和类型筛选。
- AI 整理结果以草稿展示；用户可立即处理，也可留在收件箱中逐条核对采纳或批量拒绝。
- 记录支持编辑、删除、关联研究问题与查看来源。外部链接本身不等于已读取其内容，首版不默认抓取链接页面。

### FR-02 研究地图

M2 手动部分已实现：问题/记录/发现/方向四种节点，项目地图与个人总览、跨项目一层邻居、150 节点画布、分页浏览、布局持久化、关系历史与复核；M3 已加入用户选择已有对象后的 AI 关系建议；历史回放仍未实现。

- 地图按“项目/主题 → 研究问题 → 尝试与发现”逐级展开，节点详情关联探索卡和证据。
- 支持手动创建、编辑与删除关系，按研究问题和工作/结果状态筛选。
- 首版关系类型：关联、子问题、源于、验证、支持、质疑、延伸、复用。子问题限问题节点、每个问题最多一个父问题、不能成环。
- 每条关系记录方向、类型、依据与确认状态；区分“支持某个判断”和“复用某项方法”等不同语义。
- AI 推荐关联时显示理由及来源，确认后加入正式地图。文本相似只能作为建议线索。
- 第一版优先保证小规模图谱清晰可读，采用分层展示与局部展开；地图历史回放放入后续版本。

### FR-03 个人贡献时间线

M4 已实现、待集中验证：贡献表单、六种类型、发生日期筛选、本人确认、可选固定依据、历史/恢复/复核，以及 AI 候选逐条采纳。未附材料显示用户自述；附材料仍由用户判断其支持程度，不宣称系统证明。

- 贡献类型包括提出问题、作出选择、修正建议、设计验证、形成理解、建立联系，允许后续调整。
- 每条贡献包含行为描述、发生日期、用户确认、可选关联材料和产生的影响；影响不明确时允许留空。
- 展示 AI、他人与用户各自的帮助或行动，归属依据以用户确认和可见过程记录为主。
- 从贡献详情可回到探索卡、原始片段及关联的研究问题。
- AI 可提出贡献候选，不自动宣告作者身份或计算“人类贡献百分比”。

### FR-04 成长档案与理解变化

M4 已实现、待集中验证：“我的成长”提供贡献/能力/理解三页签；能力标签同账号唯一，可归档恢复，历史保存当时名称。实例至少一个标签，“材料记录”需记录/行动/复盘，“任务实践”需完成行动及结项说明。理解变化前后文字必填，三组依据各自固定版本，支持独立创建或关联研究问题。

从记录、行动、复盘进入表单，从研究问题查看相关条目，成长详情可明确创建带来源版本的行动。周复盘可以选择贡献和成长修订；不自动评分或生成理解变化。

- 提供成长时间线、能力档案和同一问题的理解前后对照。
- 能力示例：论文判断、实验设计、结果分析、问题提出、AI 协作；用户可修改标签。
- 成长条目关联具体实例，并标明用户自述、材料记录或任务实践等依据类型。
- 可以记录“在帮助下完成”“独立完成”“迁移到新情境”等经历，允许只有一次实例或暂缺进一步证据。
- AI 协作能力可包含提出约束、核查来源、寻找反例和设计验证，不以减少 AI 使用量作为成长标准。

### FR-05 尝试复盘与暂缓管理

M2 手动部分已实现：从记录/行动进入尝试复盘，保留期待、实际、解释与重启条件；复盘不会自动改变方向或行动。

- 复盘内容包括原先期待、实际结果、已知与未知、可复用材料、继续所需条件。
- 复盘后可以继续、调整方法、暂缓或结束当前尝试，并保存原因。
- 暂缓方向可手动记录重启条件，在方向池中查看；根据新材料自动触发提醒属于后续功能。
- 失败原因属于待核实解释时，应明确标识，不能与实际观察混淆。

### FR-06 方向池与下一步计划

M2 手动部分已实现：方向状态分组与优先级筛选，独立或关联方向的行动，一句结果结项、可选多记录关联/新记录与关系原子保存、结项后带原因重新开启。M5-A 新增六类显式材料的行动候选、目标与约束、理由引用和逐条采纳，正式行动以待开始创建，方向限选本次材料中已有方向。最多 5 个候选；不生成方向或自动安排日期，资源投入明确为估计。

- 方向卡包含问题、来源、支持与反对证据、不确定性、资源需求和最小验证行动。
- 用户手动选择优先级，将方向加入当前重点，形成具体行动。
- 行动包含研究目标、可选学习目标、完成标准、预期时间和状态。
- AI 帮助补充替代解释、整理依据、拆解行动，不自动将推荐分数当作方向价值的结论。
- 完成行动后可关联新的探索卡，回到原问题或派生新分支。

### FR-07 周复盘

M2 手动部分已实现：本地自然周/自定义日期范围、手动选择固定版本材料、填写认识变化、保存后显式创建行动或调整方向。M4 增加贡献/成长材料选择及手动成长创建入口；M5-A 增加已保存周期复盘的 AI 辅助整理，参考内容仅从已关联的固定版本选择，四个字段可不采用/追加/替换，保留当前文字和最终预览；不自动生成成长或创建行动。

- 按用户选择的时间范围汇总记录、行动和判断变化，并链接原始依据。
- 先给用户表达自身判断的空间，再展示可选 AI 补充。
- 用户确认本周推进、认识变化、仍然受阻的事项和下周选择。
- 复盘产生的成长条目、图谱关系或行动均以显式选择和确认方式保存。

### FR-08 来源、导出与基本数据保护

M1 已实现账号会话、对象归属检查、原始材料/来源不可变版本及 SQLite 备份恢复；M2 实现跨模块引用待复核、固定片段与删除来源占位；M3 实现账号独立模型配置、输入范围选择和固定版本候选；M4 扩展贡献/成长固定引用及 AI 贡献候选，M5-A 增加范围预览和 JSON/Markdown 下载，删除依据仅占位、跨项目固定依据列明、变更后重新预览。

- 记录、关系、贡献与成长条目均可追踪相关来源。
- 提供基础 JSON 数据导出及可阅读的 Markdown 记录/复盘导出。
- 公开演示使用虚构或脱敏数据；多人试用时必须实现用户数据访问隔离。
- 调用外部模型前展示处理范围，支持用户选择材料；密钥仅以密文保存在服务端 SQLite 中，主密钥文件独立保存。
- 删除或修改来源后，关联内容需要标记待复核，或按明确的删除规则处理，不能继续显示为来源有效。

## 5. AI 工作流与错误处理

建议采用固定工作流：

**保存原始记录 → 提取结构化草稿 → 校验字段与引用 → 展示候选 → 用户确认 → 写入正式对象。**

| 环节 | 实现约定 |
| --- | --- |
| 内容提取 | 根据实际输入生成字段，缺少信息时留空或提出问题，不补写未发生的实验 |
| 关系建议 | 提供候选节点、关系类型、理由及来源；保留采纳与拒绝状态 |
| 贡献与成长 | 区分行为事实、用户自述和模型推断；贡献归属须由用户确认 |
| 规划建议 | 基于已有材料整理选择，明确证据缺口与约束 |
| 引用校验 | 校验来源是否存在、是否属于当前用户；引用存在不代表语义正确，仍需核对是否支持表述 |
| 调用失败 | 显示可理解的失败状态，支持重试与手动编辑，已保存的原始记录保持可用 |
| 重试与更新 | 防止重复生成正式记录；旧建议在来源变更后标记需复核 |

首版不依赖模型微调或自主多智能体流程。模型调用封装为可替换服务，提示词与结构化输出约定纳入版本管理。

## 6. 全项目逻辑对象

以下覆盖全产品逻辑对象。M1 仅落库用户、会话、项目、探索卡、记录版本、来源及来源版本；M2 新增研究内容、关系、证据、方向/行动、复盘、布局与修订，M3 增加模型配置、任务/输入、建议/事件，M4 增加贡献、能力标签、成长及版本/证据/行动来源；数据库结构以迁移文件为准，关系与数据流以[架构文档](ARCHITECTURE.md)为准。

| 对象 | 主要用途与关联 |
| --- | --- |
| 用户/个人空间 | 隔离私有数据，关联项目与所有记录 |
| 项目/主题 | 组织研究问题、探索卡和方向 |
| 研究问题 | 表达当前关注的问题，可有子问题与其他关联 |
| 探索卡 | 保存活动、观察、判断、状态和来源引用 |
| 来源材料/片段 | 保存输入、版本或外部链接，为引用提供可定位依据 |
| 图谱关系 | 连接问题、尝试与发现，记录类型、依据和确认状态 |
| 贡献条目 | 描述用户确认的行为及影响，关联探索卡与证据 |
| 能力标签/成长条目 | 记录能力实例和理解变化，关联证据与确认方式 |
| 候选方向/行动 | 连接未来问题、优先级、条件、计划与执行结果 |
| 复盘 | 汇总一段时间或一次尝试，关联判断更新和后续行动 |
| AI 建议/处理任务 | 保存待确认输出、来源版本、处理状态和采纳结果 |

共同约定：对象使用稳定标识；记录创建/更新时间与所属用户；正式结论和依据之间存在明确引用；来源变化、编辑、删除和重复提交均有确定行为。

## 7. 已落实技术方案

M1 已按 SQLite 本地文件方案实现并验证，不依赖 Docker 或独立数据库服务。每台电脑独立运行拥有自己的数据文件；同一后端可供多个账号使用，各账号之间不共享项目。

| 层次 | 采用方案 | 当前用途 |
| --- | --- | --- |
| 前端 | React + TypeScript + Vite、React Router、TanStack Query | 中文页面、路由、表单、服务端查询缓存 |
| 后端 | Python 3.12 + FastAPI + Pydantic | 会话、归属、项目、记录、导入、来源和历史 API |
| 数据库 | SQLite + SQLAlchemy 2 + Alembic | 本地持久化、事务、版本检查、自动迁移 |
| 认证 | Argon2、服务端会话、HttpOnly Cookie、CSRF 与 Origin 检查 | 七天会话与多账号独立数据 |
| 质量 | pytest、Ruff、TypeScript、Prettier、Playwright | 数据库集成、类型/构建检查、桌面与窄屏关键流程 |
| 图谱交互 | React Flow `@xyflow/react` + Dagre | 节点、连线、布局、局部展开、详情与窄屏列表 |
| AI 服务 | 用户自定义 URL/模型名/Key，httpx + 进程内执行器 + SQLite 任务表 | 探索卡草稿、已有对象关系建议与贡献候选；规划辅助待后续 |

使用节点和关系表可以支持首版图谱；是否增加图数据库或向量检索，取决于后续实际需求。首版不将这些组件设为依赖。

仓库已建立 `frontend/`、`backend/`、`docs/`；后端集成测试位于 `backend/tests/`，浏览器测试位于 `frontend/e2e/`。数据库默认位于 `data/edutoy.sqlite3`，环境配置与数据均不进入 Git。模型提示词与输出结构已纳入版本管理（m3.v1，贡献候选 m4.contributions.v1）。

前后端接口、数据校验、归属、事务、版本、错误与 AI 状态边界已经写入架构文档。真实安装、启动、验证与备份命令见 README。业务导出格式 `yanji.business.v1` 已在 M5-A 落实：白名单当前内容、实际引用的固定版本和范围外链接摘要，不含应用凭据、完整 AI 任务或未采纳候选；5,000 条/20 MiB 上限。集中验证与运行交付仍由 M5-B 跟踪。

## 8. 首版范围与后续扩展

### 8.1 首版交付目标

FR-01 至 FR-08 的基本流程都属于首版目标，允许先完成手动版本，再接入 AI 辅助。开发顺序见进度文档。首版必须能通过一个完整故事串起记录、研究关系、判断与成长、复盘及下一步行动。

M1 是其中的记录基础阶段，M2 完成手动研究和行动闭环，均不表示整个含 AI/成长的首版发布。M1 验收演示为：账号 A 注册 → 建项目 → 导入中文 Markdown → 补充判断 → 查看来源和历史 → 搜索 → 删除恢复 → 账号 B 确认不可见 → 重启后 A 的数据保持完整。

### 8.2 后续版本候选

- 图谱历史回放与跨时间比较。
- GitHub、文献管理工具或对话平台的自动同步。
- PDF、图片或复杂实验文件解析。
- 跨项目关联的自动发现和暂缓方向的条件触发提醒。
- 自选内容生成组会汇报、分享视图和团队协作空间。

上述功能不阻塞首版发布。公开排名、自动贡献占比、论文署名裁定和心理诊断不属于产品功能。

**M2 验收故事：** 项目 A 问题 → 关联未达预期实验 → 带条件发现与原文证据 → 项目 B 方向 → 最小行动 → 结项与可选结果记录 → 尝试/周复盘 → 显式后续行动；来源更新、删除恢复、账号隔离和重启后内容布局保持正确。

## 9. 首版验收标准

以下标准是本项目建议的验收要求，不是教师额外规定。

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| AC-01 | 保存与导入 | 文本/Markdown 可保存并重开；缺少可选字段不阻止录入；原始内容可查看 |
| AC-02 | AI 草稿确认 | 能修改、采纳或拒绝建议；拒绝的建议不会进入正式图谱或贡献档案 |
| AC-03 | 研究脉络 | 能从问题查看尝试、结果与后续方向；关系类型、方向和依据可查看 |
| AC-04 | 贡献与成长 | 至少能手动创建并查看一条有依据的贡献和成长记录；AI 候选须确认 |
| AC-05 | 受阻与暂缓 | 能区分工作状态与结果判断，记录原因和重启条件并再次找到它们 |
| AC-06 | 计划闭环 | 能从候选方向建立行动，关联执行结果，并通过复盘调整下一步 |
| AC-07 | 失败恢复 | 模型超时、输出格式错误或引用缺失有明确反馈；原始记录仍可用；重试不会重复入库 |
| AC-08 | 数据一致性 | 来源变更后关联引用不再被误标为有效；基本导出可读且关联标识一致 |
| AC-09 | 数据隔离 | 多用户环境下不能通过修改请求中的对象标识读取或改动他人私有记录 |
| AC-10 | 交付可运行 | 新环境可按 README 完成安装与启动；示例数据与真实功能的状态标注准确 |

验证包括数据与接口测试、关键路径集成/端到端测试，以及固定样例上的 AI 输出核对。人工核对重点是字段是否忠于输入、引用是否支持表述、建议是否保留不确定性。详细步骤、用例编号、执行与缺陷模板见[功能测试文档](FUNCTIONAL_TESTS.md)，每次后续功能开发和修复须同步更新。当前按用户安排先开发、后续集中测试；实际结果与已知问题记入测试批次及进度文档，不将待执行写为通过。

## 10. 团队协作与课程交付

建议 5 人分别牵头需求与记录交互、图谱与成长展示、后端与数据、AI 与评估、质量与交付。具体成员尚未分配；每人参与实现与交叉审查，质量工作由全组共同承担。

按可演示的完整用户故事组织迭代，保留“需求编号 → 开发任务 → 代码变更 → 验证结果”的对应关系。课程过程材料可随实现积累，包括需求说明、原型、架构与数据设计、接口说明、质量检查、测试记录、部署说明和演示材料。

推荐的演示故事：导入一条未达预期的实验记录，确认自己的判断和证据，查看它在研究地图中的位置，记录理解变化，再选择下一次验证行动。演示必须明确哪些结果来自真实调用，哪些材料属于预置示例。
