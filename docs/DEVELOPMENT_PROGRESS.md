## 7. 更新规则

1. 开始一项任务时，标明任务 ID、负责人和当前状态。
2. 实现完成但尚未验证时，标记“待验证”；达到验收条件后再标记“已完成”。
3. 每次有实质变更时追加工作日志，写明做了什么、如何检查、还有什么问题。
4. 范围或架构变化同步修改项目说明，并追加决策记录。
5. 保留已完成历史；明确阻塞项及其影响，不将待办或设计文档写成已实现功能。
6. GitHub 同步状态以实际提交与推送结果更新；提交标识可在后续记录中补充，完整历史以 Git 为准。
