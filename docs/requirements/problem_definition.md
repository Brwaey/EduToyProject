## 一、5W1H 问题定义

| 维度 | 问题与场景 | 对产品的含义 |
| --- | --- | --- |
| **Who｜谁遇到问题** | 主要用户是处于论文阅读、实验复现和早期课题探索阶段的研究生。他们会使用笔记、实验记录、论文或代码链接以及 AI 工具开展研究。课程项目组成员负责共同开发和验收产品；应用内的研究资料按账号隔离，当前不提供组内共享空间。 | 面向研究者个人的长期记录和反思；项目组共同开发、测试和演示产品。 |
| **What｜要解决什么问题** | 研究问题、原始材料、实验过程、结果判断、AI 建议和待办行动可能分散保存。时间拉长或判断改变后，用户可能难以快速找回“当时做了什么、依据是什么、为什么改变想法、下一步是什么”；未达预期的尝试及其适用条件也容易失去上下文。 | 把研究记录、证据、用户判断、方向、行动、复盘和个人成长线索关联起来，并保留版本与来源，方便回看和继续探索。 |
| **When｜何时发生** | 阅读论文或资料后、完成一次实验或尝试后、与 AI 协作后、研究判断发生变化时，以及定期复盘或重新启动暂缓方向时。 | 记录应允许先快速保存，再逐步补充结构化信息；回顾和计划应能从已有材料进入，而不要求用户一次完成全部信息。 |
| **Where｜在什么情境发生** | 研究活动通常跨越多个工具和较长时间。当前产品通过本机运行的 Web 应用提供服务，默认把数据保存在本地 SQLite 文件中；用户配置并发起模型任务时，选定材料会发送给所配置的兼容模型服务。 | 默认按个人空间保存和隔离资料；用户明确选择模型输入及导出范围。当前版本不提供公网托管、跨设备数据同步或团队共享工作区。 |
| **Why｜为什么值得解决** | 研究者需要理解证据如何支持或限制判断，区分实际观察、解释和模型建议，并能依据当前认识选择下一步。回顾具体贡献和前后理解变化，可以为个人研究经历提供可查的事实与语境。 | 支持可追溯的研究过程、自主判断与下一步选择。提升学习效果、能力或掌控感属于设计目标，需另行评估，不能由功能存在直接推出。 |
| **How｜产品如何回应** | 用户先保存原始记录，再补充行动、观察、判断与证据；将记录关联到研究问题、发现和方向；通过行动、尝试复盘和周期复盘继续推进；按需记录贡献、能力实例和理解变化。AI 仅对用户选择的材料提供草稿或建议，用户核对后才采纳。 | 以“保存材料 → 整理判断与关系 → 回顾证据和变化 → 选择下一步 → 保留新结果”的循环连接主要功能；允许全程手动使用，并提供业务数据导出。 |

### 问题陈述

在长周期且充满不确定性的研究过程中，研究生需要在论文、笔记、实验结果和 AI 协作材料之间反复切换。若研究问题、证据、个人判断、行动和后续反思彼此分离，用户就难以还原判断形成的过程、识别结论适用的条件，并据此决定下一步。产品希望帮助用户把这些材料按研究脉络连接并持续回看，同时保留用户对解释、贡献归属和 AI 建议的最终判断权。

## 二、产品描述

### 一句话描述

**研迹是一款面向研究生个人使用的 AI 协作科研成长支持系统，围绕研究问题连接科研记录、尝试证据、个人判断、复盘与下一步行动，让研究过程和个人学习线索能够被追溯与继续推进。**

### 目标用户与使用边界

- **核心用户：**需要管理论文阅读、实验复现和早期研究探索的研究生。
- **常见场景：**保存随手记、阅读记录、实验尝试、AI 协作和灵感问题；回顾结果与证据；整理研究脉络；计划行动；记录贡献或理解变化。
- **当前账号模型：**同一后端可以服务多个账号，但各账号的项目、科研记录和模型配置相互隔离；这不等同于组员共享研究项目。
- **当前运行边界：**本机 Web 应用与 SQLite 持久化；GitHub 同步代码和文档，不同步本地数据库、账号或科研资料。

### 核心能力

1. **科研记录：**用随手记、论文阅读、实验尝试、AI 协作或灵感疑问保存过程材料，逐步补齐结构化探索卡；保留原文、来源和修订历史。
2. **研究地图：**连接研究问题、记录、发现和候选方向，查看跨项目脉络及关系依据；正式关系由用户建立或确认。
3. **行动与复盘：**围绕方向创建具体行动，记录尝试结果，保存尝试复盘或周期复盘，并由用户选择继续、调整或暂缓。
4. **贡献与成长：**记录用户确认的贡献、能力实例和同一问题的理解变化；保留相应材料版本，不生成能力总分或贡献比例。
5. **可选 AI 协作：**使用用户自设的兼容模型服务，针对明确选择的材料生成整理草稿、关系候选、贡献候选、行动建议或复盘辅助内容；用户可以核对、修改、采纳或拒绝。
6. **数据带出：**按用户选定的范围预览并导出业务 JSON 或 Markdown；数据库备份用于本地恢复，和业务导出用途不同。

### 典型使用流程

研究生保存一条论文或实验记录，补充自己采取的行动、观察到的结果和当前判断，再将它关联到一个研究问题。随着材料增加，用户整理发现及其条件，选择值得继续的方向并创建行动；完成尝试后记录结果和复盘，必要时更新个人贡献或理解变化。AI 可以在用户选材后提供候选内容，但不会未经确认写入正式研究结论或自动创建后续工作。

### 设计原则

- **先记录，后整理：**低门槛保存原始材料，结构化字段可以后补。
- **证据可追溯：**用户判断、原始材料、AI 建议和后续修订应能区分；材料变化时提示用户复核。
- **用户决定正式内容：**AI 输出是草稿或建议；采纳、拒绝、修改和下一步选择由用户控制。
- **保留不确定性：**允许“证据不足”“暂时无法解释”或“当前条件下未支持”，不把失败自动包装为成功经验。
- **尊重个人数据边界：**模型处理和导出前明确选择范围；研究资料默认保留在个人数据空间。

### 当前版本不覆盖的内容

当前版本不提供应用内团队共享项目、组员间数据协作、云端托管或跨设备同步；不自动抓取外部网页、不解析 PDF/图像、不自动生成研究结论或日程；不对能力、焦虑、作者身份或贡献比例进行评分和裁定。后续是否扩展由团队按需求和验收结果决定。

## 三、验证边界

本报告记录的是产品问题假设与已确定的设计方向。应通过实际使用和测试继续观察：用户是否能快速记录材料、能否找回判断依据、能否区分观察与解释、AI 候选是否容易核对，以及行动和复盘是否帮助用户推进自己的研究。自动化测试通过只说明指定软件行为满足相应检查，不单独证明产品价值或学习效果。功能实现和验证状态以[开发进度](../DEVELOPMENT_PROGRESS.md)及[功能测试文档](../FUNCTIONAL_TESTS.md)为准。
